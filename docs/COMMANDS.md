# 命令与配置

## 通用命令

`fls.sh`、`fls-t.sh` 和模块里的 `fls-a.sh` 都支持以下核心动作：

| 命令 | 作用 |
| --- | --- |
| `start` | 启动面板 |
| `stop` | 停止面板 |
| `restart` | 重启面板 |
| `status` | 查看状态、目录、端口和 PID |
| `log` | 查看实时面板日志 |
| `update` | 拉取仓库更新 |
| `clone` | 强制重新拉取仓库并覆盖程序文件 |
| `ensure-repo` | 程序不完整时才拉取仓库 |
| `bstart` | 创建并启用对应平台的自启 |
| `rstart` | 移除对应平台的自启并重启 |

命令只替换程序文件，`data/`、`log/` 和 `scripts/` 应保留。

## 端口和 Token

启动参数：

```bash
sh fls.sh start -p 5701 -t 123456
sh fls.sh restart --port 5701 --token 123456
```

环境变量：

```bash
FLS_PORT=5701 FLS_TOKEN=123456 sh fls.sh restart
```

默认端口为 `5700`。如果没有 Token，首次访问 `/setup` 设置管理 Token。

## 目录变量

原生 Linux/Termux 控制脚本：

| 变量 | 作用 |
| --- | --- |
| `FLS_BASE_DIR` | 覆盖项目目录 |
| `FLS_PYTHON` | 指定 Python 解释器 |
| `FLS_REPO_URL` | 覆盖仓库地址 |
| `FLS_REPO_BRANCH` | 覆盖仓库分支 |
| `FLS_PORT` | 面板端口 |
| `FLS_TOKEN` | 临时管理 Token |
| `FLS_TRUSTED_PROXIES` | 可提供 `X-Forwarded-For` 的代理 IP/CIDR，逗号分隔；默认不信任任何代理 |
| `FLS_ALLOW_QUERY_TOKEN` | 设为 `1` 临时启用 URL 查询 Token 兼容；默认禁用，优先使用登录页或 `X-Token` |

Termux 专用变量见 [TERMUX.md](TERMUX.md)，KernelSU/Magisk 容器变量见
[ANDROID_MODULE.md](ANDROID_MODULE.md)。

## 依赖与运行器安装

在面板“依赖管理”（`/deps`）安装 Python 包，或在“面板状态”（`/panel/status`）
安装运行器后，会进入同一个安装日志页。Windows 的运行器安装入口会跳转到官方下载页。

日志页会显示安装中、安装成功、安装失败或启动失败，以及进程退出码。退出码 `0`
表示安装命令成功结束；其他退出码表示失败，具体原因见日志。启动失败没有退出码，
页面会保留生成命令或启动进程时的错误。安装后可用“刷新依赖检测结果”检测 Python
核心依赖；运行器请返回“面板状态”确认可用性。

安装记录保存在面板进程内存中。面板重启或记录被淘汰后，原链接显示“无法追踪”；
旧记录缺少退出码时显示“结果未知”。这两种状态均不能证明安装成功，请到日志管理
查找 `deps-install-*.log` 或 `system-install-*.log`，并重新检测依赖或运行器。

日志 API `GET /api/deps/install-log/<install_id>` 保留 `running` 和 `log`，并提供：

| 字段 | 含义 |
| --- | --- |
| `status` | `running`、`succeeded`、`failed`、`start_failed`、`unknown` 或 `missing` |
| `status_label` | 对应的中文状态 |
| `returncode` | 进程退出码；尚未退出或无法取得时为 `null` |
| `error` | 失败或无法确认结果的原因；正常运行和成功时为空字符串 |

面板状态（`/panel/status`）每次检测脚本运行器时，每项版本命令最多等待 3 秒，最多同时
执行 4 项检测。非零退出、超时和无法执行会显示为检测异常；只有确认找不到
可执行文件时才显示安装操作。检查异常原因后可选择“重新检测”。检测命令会使用任务实际
配置的 `FLS_PYTHON`、`FLS_BASH` 和 `FLS_NODE`。

在线脚本安装使用后台作业和独立安装日志。同一脚本已有活跃安装时不会重复启动，
准备中或下载阶段收到停止请求后会在下一检查点取消；每次网络读取最多等待 60 秒。
`GET /api/online-scripts/log/<install_id>` 的结果约定为：

| HTTP 状态码 | 含义 |
| --- | --- |
| `200` | 安装记录存在；包括准备中、运行中、停止中、停止失败及所有终态 |
| `404` | 安装 ID 不存在，日志不会被读取 |
| `400` | `lines` 不是整数 |

`POST /api/online-scripts/install-stop/<install_id>` 返回 JSON 字段 `ok` 和 `msg`：

| HTTP 状态码 | 含义 |
| --- | --- |
| `200` | 已接受停止请求；应继续轮询日志 API，直到 `running=false` |
| `404` | 安装 ID 不存在 |
| `409` | 已结束、重启后结果未知，或终止后进程仍存活；`msg` 保留具体原因 |
| `500` | 无法保存停止请求等服务错误，`msg` 保留原始错误 |

页面停止入口成功时跳转，失败时用相同的 `404`、`409`、`500` 显示原因。
安装线程启动或初始快照写入失败时返回 `500`，释放活跃占位，并提供安装记录链接。

在线脚本安装快照保存在 `data/online_install_jobs.json`，只保存状态、退出码、错误和日志路径，
不保存线程或进程句柄。终态包括“已完成”“失败”“启动失败”“超时”“已停止”和“结果未知”。
每条 Git 或安装命令最多运行 1800 秒，超时后先终止、再强制终止，各等待最多 1 秒。
无法确认进程退出时保持 `running=true`，显示“停止失败”或“超时（停止失败）”，阻止重复启动；
可再次请求停止，进程实际退出后才写入终态。`returncode` 保留真实进程退出码，
未启动进程或无法取得时为 `null`；下载失败等错误不会伪造退出码。
日志页持续显示最终错误和退出码。面板重启后运行中的安装显示“结果未知”，保留原诊断，
请检查日志和脚本目录后再重试；已完成的结果保持原状。停止不会撤销此前已写入的脚本或已导入的任务。

raw 文件先流式下载到目标目录内唯一的 `.fls-download-*.part` 文件，完整接收、写盘和设置权限后
才原子发布到正式路径。下载失败、读取超时或发布前取消时，已有脚本保持完整，新脚本不会留下半文件；
响应连接会关闭，并清理本次临时文件。未确认覆盖时，即使下载期间目标被其他操作创建，也会报错并保留该目标。
确认覆盖后的并发下载以最后一次完整发布为准，不会混合文件内容；覆盖保留原文件权限，Shell 脚本添加可执行权限。
面板被强制结束时可能留下未发布的 `.part` 文件，正式脚本不受半文件影响；确认无活跃安装后可手动处理残留。
写盘、权限或原子发布失败会保留原始错误，不会继续执行安装命令；临时文件清理失败会记入安装日志。

在线脚本源刷新通过 `POST /api/online-scripts/refresh` 或在线脚本页面的“同步在线脚本源”提交后台任务。
同一面板进程内同时只允许一个刷新请求；重复请求返回 `409`，不会覆盖当前任务。提交成功返回 `202`
和刷新 ID，线程启动失败返回 `500` 并保留真实错误。`GET /api/online-scripts/refresh-status` 返回
`running`、`status`、`message`、`error`、`updated_at` 和日志路径；状态包括运行中、已完成、失败、启动失败
和结果未知。远程请求超时属于失败状态，错误文本保留超时原因，旧缓存继续可用。

刷新状态持久化在 `data/online_script_refresh.json`。面板重启后如果快照仍为运行中，会改为“结果未知”，
不会声称远程同步已完成。新缓存先写入数据目录内的临时文件，再用原子替换发布；抓取、解析、写盘或替换失败
都保留旧缓存。脚本源和外部任务源的 HTTP 响应会在读取后关闭。

从在线脚本导入任务时，脚本任务标识检查和写入 `data/tasks.json` 在同一原子更新中完成；重复提交只会新增一次，
并发导入不同脚本不会互相覆盖，任务写入及对应的调度器重载按顺序执行。写入失败会显示实际存储错误，且不会报告导入成功或重载调度器。
任务已经写入但调度器重载失败时，页面会明确说明已持久化及重载错误；重复提交仍会按任务标识跳过。
普通任务新建、编辑、启停、删除、批量和合集操作，以及运行次数更新也使用同一进程内的原子任务变更；
任务文件保存与需要的调度器重载按相同顺序执行，避免并发入口互相覆盖任务或留下旧调度状态。

## 日志查看

面板的任务、脚本调试和安装日志每次最多读取末尾 `1 MiB`，正文最多显示 `5000` 行。
日志 API 的 `lines` 参数必须为整数，超出行数范围时限制到 `1-5000`；非法参数返回 `400`。
达到字节上限时会显示“日志过长”提示，并省略截断处的不完整行。原始日志文件不会改写，
完整内容保存在安装目录的 `log/` 中。

## 运行历史分页与导出

`/history` 每页显示 30 条记录。`page` 不是整数或小于 1 时按第 1 页处理，超过最后一页时显示最后一页；
分页链接会保留当前 `q` 关键词和 `status` 状态筛选。未知状态值按“全部状态”处理，不会返回服务器错误。
`/history/export` 使用同样的 `q` 和 `status` 筛选导出全部匹配记录，不受当前页面或 `page` 参数影响。

## 停止脚本调试

脚本调试日志页中的“停止调试运行”只在确认调试进程退出后才标记为已结束，
并保留实际退出码。停止时先请求正常终止，最多等待 1 秒；仍未退出时强制终止，
再最多等待 1 秒。进程提前退出时立即结束等待。Linux/Termux 会向调试进程组发送信号，
Windows 会终止调试进程本身，不保证终止其派生进程。

`POST /scripts/debug-stop/<debug_id>` 的结果如下：

| HTTP 状态码 | 含义 |
| --- | --- |
| `302` | 已确认退出，返回原页面；手动停止时记录“用户手动停止” |
| `302` | 调试已经结束，返回原页面；保留原退出码和错误，不追加手动停止记录 |
| `404` | 调试记录不存在或面板已重启，无法定位要停止的调试运行 |
| `409` | 进程仍存活或无法确认退出，保留进程引用和运行状态，不报停止成功 |

停止失败页可返回调试日志重试。调试记录是内存状态，缺少进程信息时不能证明已退出；
此时请检查面板进程和对应的 `script-debug-*.log`。停止不会删除日志或脚本文件。

## 停止任务与运行状态

任务运行有四个可见阶段：启动中、随机延迟中、运行中和已结束。启动或延迟阶段没有子进程时，
停止会取消本次运行并把历史标记为“手动停止”；运行中只有确认进程退出后才会返回停止成功。
Linux/Termux 会先向进程组发送正常终止信号，最多等待 1 秒，再强制终止并最多等待 1 秒；
Windows 对任务进程执行同样的有界等待。任务退出后会保留实际退出码，停止失败不会删除运行状态。

任务停止接口的结果如下：

| 入口 | 成功 | 任务不存在 | 已自行结束 | 仍存活或无法确认 |
| --- | --- | --- | --- | --- |
| 页面 `POST /stop/<task_id>` | `302` 返回来源页 | `404` | `409` 结束页，保留退出码说明 | `409` 失败页，可返回日志重试 |
| API `POST /api/task/action/stop/<task_id>` | `200`，`ok=true` | `404` | `409`，`ok=false` | `409`，`ok=false` |

批量停止会在结果中分别统计已结束、未运行和停止失败；停止失败的任务不会被删除或允许新的
同任务运行，原始系统错误会写入任务日志。面板重启会丢失内存中的进程句柄和待重试计时器。
启动时会把没有结束时间的“启动中 / 延迟中 / 运行中”历史记录改为“结果未知”，保留原说明、日志路径和退出码，
但不会声称外部进程已经退出；请检查日志、系统进程和重新运行结果。已结束、失败、超时和手动停止记录不会被这次恢复改写。

## 备份恢复限制

备份创建是后台作业。作业快照保存在 `data/backup_jobs.json`，只保存可恢复的元数据，
不保存线程、事件或进程句柄。`GET /api/backup/job/<job_id>` 会返回当前进度和最终结果：

| HTTP 状态码 | 含义 |
| --- | --- |
| `200` | 作业存在；包括已完成、失败、超时、已取消，以及面板重启后标记为“结果未知”的快照 |
| `404` | 从未保存过该 ID，或记录已被淘汰 |
| `409` | 取消请求无法执行：作业已结束，或面板重启后已失去取消所需的进程句柄 |

面板重启后，持久化的运行中作业会显示“结果未知”，并保留明确说明；这不代表归档一定完成。
请检查备份列表和日志，确认没有可用归档时重新创建。依赖列表采集超过超时时间会标记为“超时”
并保留原错误，部分生成的归档会被删除。取消、失败和超时都不会留下可下载的半成品。

以下面板环境变量在启动时读取，设置后需重启 FLS：

| 变量 | 作用 | 默认值 |
| --- | --- | --- |
| `FLS_BACKUP_MAX_UPLOAD_MB` | 备份上传大小上限，正整数 MiB | `512` |
| `FLS_BACKUP_MAX_EXTRACTED_MB` | 归档解压后总大小上限，正整数 MiB | `2048` |
| `FLS_BACKUP_MAX_ARCHIVE_ENTRIES` | 归档成员数上限，正整数 | `10000` |

## `ensure-repo` 和 `clone`

- `ensure-repo`：检查 `fls-manager.py`、`fls_manager/` 和 `fls.sh`，缺失时才拉取。
- `clone`：不管当前是否完整，都从仓库重新拉取；适合本地文件损坏或更新失败。
- `update`：优先在现有 Git 仓库执行 fast-forward 更新；非 Git 目录会重新拉取。
