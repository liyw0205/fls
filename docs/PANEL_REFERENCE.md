# 同类面板参考

更新时间：2026-07-03

本文用于阶段 2 之后的产品对标。青龙面板、呆呆面板、白虎面板只作为信息架构、交互流程和功能演进参考，不直接照搬技术栈或代码。

参考来源：

- 青龙面板：`https://github.com/whyour/qinglong`
- 呆呆面板：`https://github.com/linzixuanzz/daidai-panel`
- 白虎面板：主仓库来源待阶段 2 继续核验；当前仅按公开介绍和生态脚本适配信息作为产品方向参考。

## 参考边界

- FLS 当前定位仍是 Flask + 原生 CSS/JS + JSON 文件存储的轻量脚本管理面板。
- 参考对象的前后端技术栈、数据库、构建链不直接迁移到 FLS。
- 优先借鉴用户工作流：任务管理、脚本管理、环境变量、日志、通知、订阅、依赖、运行时、移动端操作。
- 涉及远程命令执行、开放 API、跨节点互联、多用户权限时，必须先做最小权限和安全边界设计。
- 如后续复用开源代码、样式、图标或协议，必须单独确认许可证和维护成本。

## 青龙面板

公开定位：

- 面向定时任务、脚本、环境变量、配置文件、日志和依赖管理的成熟任务面板。
- 生态中已有大量脚本和订阅使用习惯。

FLS 可借鉴：

- 导航结构：任务、脚本、环境变量、配置、日志、依赖、通知、系统设置分组清晰。
- 任务操作：运行、停止、禁用、日志、配置入口需要在桌面和移动端保持高频可达。
- 环境变量：批量导入、搜索、备注、启停、隐藏敏感值。
- 日志体验：任务日志和系统日志需要区分，实时日志需要保留自动滚动和暂停查看。
- 订阅思路：在线脚本源可以继续向“订阅源 + 安装任务 + 更新日志”演进。

FLS 不直接照搬：

- 不引入 Node/npm 作为运行期必需依赖。
- 不为了 UI 一致性重写为前后端分离架构。

## 呆呆面板

公开定位：

- 轻量现代的任务面板方向，常见描述包括 Go、Vue3、SQLite、低占用、依赖管理、通知渠道、Open API 等。

FLS 可借鉴：

- 轻量优先：功能扩展不能牺牲低资源占用和部署简单。
- Open API：后续可设计只覆盖任务运行状态、任务动作、日志读取、脚本源刷新等稳定接口。
- 通知渠道：继续完善通知测试、默认通知、任务级通知覆盖关系。
- 依赖管理：依赖安装日志、运行中状态和失败重试提示需要更统一。
- 移动端：小屏优先展示任务状态、运行/停止、日志入口，复杂配置放入详情页。

FLS 不直接照搬：

- 不切换 Go/Vue/SQLite 作为默认架构。
- 不在缺少权限模型前开放过宽 API。

## 白虎面板

公开定位：

- 常见描述强调高性能、低资源占用、多运行时环境、节点互联和跨节点环境变量同步等方向。

FLS 可借鉴：

- 运行时管理：当前 FLS 已有 `runtime.py`，后续可把 Node、Python、Shell、PowerShell、Java 等运行时检测和安装日志做成统一模型。
- 多节点方向：先抽象“节点状态”和“远程任务动作”的数据结构，再考虑实际互联。
- 环境变量同步：如果后续做多节点，必须先明确变量作用域、敏感值脱敏和冲突策略。
- 高性能方向：长日志、任务列表和运行状态 API 应避免一次返回过大内容。

FLS 不直接照搬：

- 阶段 2 不做节点互联。
- 不在单机模型未稳定前引入分布式状态。

## 阶段 2 可落地事项

优先落地：

- 继续优化响应式任务列表、表单、日志、脚本管理和配置页。
- 新增轻量页面结构烟测，弥补当前环境缺少真实浏览器截图的问题。
- 整理页面组件抽取候选，优先抽取不涉及业务状态的卡片、工具栏、分页和表单块。

暂缓：

- 多用户权限。
- 跨节点互联。
- 大规模 API 设计。
- 切换前端框架或引入 npm 构建链。

## 候选需求池

- 任务详情页：整合基础信息、最近日志、运行历史、环境变量、通知策略。
- 环境变量批量操作：启停、搜索、脱敏显示、从任务导入。
- 在线脚本订阅：源健康检查、刷新记录、安装历史、任务导入预览。
- 运行时中心：统一展示 Python/Node/Shell/Java/PowerShell 可用性、安装日志和修复建议。
- 移动端快捷操作：任务运行、停止、查看日志、复制命令、筛选状态。
- Open API 草案：先覆盖只读状态和少量动作接口，并要求 Token/权限边界。
