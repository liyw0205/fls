# 高频入口性能基准

## 范围与方法

本阶段只测真实前端/API 调用链：`GET /` 与 `GET /api/dashboard/runtime`（仪表盘及其动态刷新）、
`GET /history`（浅分页、深分页、关键词搜索）、
`GET /log/<task_id>`（详情历史）、`GET /api/status`（状态列表）和
`POST /api/task/action/toggle/<task_id>`（状态变更），以及历史页按钮触发的
`GET /history/export`（全量 CSV 导出）。基准在临时 `FLS_BASE_DIR` 中
生成固定 10,000 条历史和 100 个任务，Flask `test_client` 从请求开始计时到响应体
序列化完成；不连接生产服务，不生成百万用户/记录。

每个场景预热 2 次、采样 12 次，报告 p50/p95/p99、吞吐、错误数/错误率、CPU 时间、
峰值 RSS、平均/最大响应字节。基线通过 `FLS_DISABLE_HISTORY_INDEX=1` 模拟原始的
JSON 全量读取；优化组使用派生 SQLite 索引和 storage 锁。结果写到 `/tmp`，不是仓库
资产。

所有 API 或 Playwright 重测都必须先执行：

```bash
tools/run_performance_benchmark.sh --mode optimized --iterations 12 --playwright
```

推荐使用 `tools/run_performance_benchmark.sh`，锁被占用时它在创建临时 fixture、测试
服务或浏览器前退出。Playwright 缺少 Python 包或 Chromium 时只报告 `skipped`，不伪造
通过。

任务/日志的聚焦回归和真实日志尾读响应对照使用一个入口：

```bash
tools/run_fast_regression.sh --all
```

入口先在一条 pytest 进程中独立验证各类日志路由、脱敏/截断边界和详情历史查询，再对同一
10,000 条历史、100 个任务及 7.68MB 任务日志 fixture 各执行 40 次 legacy/current 日志 API 请求。
fixture 只生成一次；该文件尾读路径不使用 SQLite 索引。两个隔离 worker 共用 fixture；报告响应
p50/p95/p99、吞吐、CPU、RSS、响应大小、错误率、响应哈希。`--tests-only` 与
`--benchmark-only` 可单独执行一层，但两层串行验收应使用 `--all`，由一个 flock 覆盖整个流程。

比较器固定请求 `GET /api/log/bench-task-0001?lines=1200`。legacy 对整段尾部文本执行原有
Unicode 不区分大小写 marker 正则；current 对 ASCII 文本先用小写字面 marker 查找，非 ASCII
仍使用原正则。后续脱敏替换、Unicode 解码、返回行数和 1MB 读取上限不变。

远程 Linux 性能基准和开发测试使用 `/home/nonebot-shared-venv/bin/python`；仓库 Linux
安装/运行默认仍使用 `/root/myenv`。Docker、Windows 和 GitHub Actions 继续使用各自隔离的解释器配置。

## 回归门槛

在相同 10k fixture、12 次采样和共享锁下，优化组应保持 0 错误；p95 上限为首页 50ms、
runtime API 20ms、浅页 5ms、
深分页 8ms、搜索 15ms、详情 5ms、状态 5ms、toggle 15ms、全量导出 125ms；峰值 RSS
不超过 128MB。
机器差异较大时，以 CI 同一 runner 的连续两次结果为比较基线，不能放宽数据规模或跳过
锁。失败时保留 stdout JSON 和 stderr 日志到 `/tmp` 供定位，不把临时数据库或结果提交。

`GET /api/status` 是任务页和外部面板轮询使用的高频入口。旧路径每次请求都重新读取并规范化
`tasks.json`，逐任务获取运行态，并重复构造相同的静态字段和 JSON 响应。当前实现增加了三个
有界读优化：只读路径通过任务文件设备号/inode/mtime/大小签名复用规范化任务列表；状态 API 在
同一任务签名下缓存安全的静态字段和序列化响应；运行态用一次批量快照在锁内读取，运行态或任务
文件变化会改变缓存 key，任务写入仍通过原子替换并清除缓存。legacy worker 显式关闭这些缓存并
使用逐任务 `is_running`，以模拟原始 develop 路径。
